Approval levels: who an Always Allow is for

ahpw's question card for a shell command, with the host's options. Allow Once is the main button, the caret opens the rest in groups, and Skip stands alone. New options are in blue here only, to tell them apart; the real card draws them as the others.

1. A member, the menu open

bob is a member: he holds chat:answer and not config:permissions. He is offered the session's level, his own level, and Allow All in this Session. No option writes the host's rules.

bob's session, as bob sees it

Always Allow Exact Command for Me
Allow All Commands in this Session

2. An admin, the menu open

alice holds config:permissions, so the host's level is offered too: it applies in every person's sessions, automations included.

3. A host with no users file

One person is the host, as in VS Code: the host's level is that person's, so the card keeps VS Code's labels and no "for Me" level.

4. Auto-approve locked by the operator

Where autoApprovePolicyRestricted is set, the host leaves out Allow All Commands in this Session, and refuses it if a client sends it anyway.
